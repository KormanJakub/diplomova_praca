# Audit aplikácie — 14. september 2026

## Rozsah a metóda

Statická kontrola backendu ASP.NET Core (`api/nia_api`), jeho testov a relevantného toku v Angular aplikácii (`web`). Neprebehlo penetračné testovanie nasadenej služby ani volania na produkčnú databázu. Nálezy sú správanie vyplývajúce zo zdrojového kódu; stav skutočného nasadenia treba osobitne overiť. Súčasný čistý výsledok auditu balíkov neznamená, že je bezpečná samotná aplikácia.

## 3. Poradie práce a cieľová architektúra

1. **Zastavenie P0 rizík.** Vypnúť seed, uzavrieť admin/file/order mutácie a úniky v DTO. Súčasne pripraviť rotáciu tajomstiev. Ak je API nasadené verejne, tieto veci majú prednosť pred vizuálnym redizajnom.
2. **Zjednotiť objednávku a platbu.** Jeden `OrderService` vlastní vytvorenie objednávky, výpočet ceny z databázy, priradenie Stripe session, potvrdenie podpísaným webhookom, sklad a idempotentné prechody stavov. Kontrolér iba validuje požiadavku a vracia DTO. Rozlíšiť online platbu a bankový prevod v stavovom modeli.
3. **Opraviť účty.** Migrovať hashe pri úspešnom prihlásení, opraviť reset cez jednorazový token, zaviesť rate limit a validačné pravidlá. Nevydávať žiadny interný `User` model v odpovedi.
4. **Zjednodušiť hranice modulov.** `Auth`, `Catalog`, `Orders`, `Payments`, `Media`, `Admin` ako aplikačné služby s úzkymi vstupnými/výstupnými DTO; Mongo vrstva zodpovedá za perzistenciu a indexy, nie HTTP kontroléry. Namiesto veľkého jednorazového prepísania presúvať vždy jeden tok s charakterizačným testom.
5. **Frontend po stabilizácii API.** Jedno centrálne API nastavenie pre prostredie, jednotný HTTP klient/interceptor, typované odpovede a ošetrenie chýb; potom UX, prístupnosť, výkon a vizuálny návrh.

## Bezpečné overenie prvej etapy

- Vytvoriť oddelenú testovaciu MongoDB alebo kontajner a testovacie Stripe prostredie; existujúce integračné testy obsahujú vzdialený connection string a nesmú sa spúšťať proti nej bez izolácie.
- Charakterizačné testy: anonymný/obyčajný používateľ/admin na admin trasách; cudzia objednávka; zmena `IsAdmin`; neoprávnené potvrdenie platby; nahranie nepovoleného súboru; paralelné vytvorenie objednávok.
- Kontrola kompilácie a frontend buildu po každej malej zmene; staging skúška celého checkoutu pred nasadením.
